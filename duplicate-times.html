Investigation of Duplicate Timestamps

Table of Contents

  • 1. Total duplicate timestamps
  • 2. ID wise duplicate timestamps

As I reported in the previous meeting, there seem to be data points that have the same timestamp for an id, but different locations. Now, irrespective of there being same or different locations, I believe that there shouldn't exist any rows for the same timestamp either. I decided to check on the entire data between <2020-01-01 Wed> and <2020-12-31 Thu>.

1. Total duplicate timestamps

If the count of unique timestamps is more than the total rows that we have, that means that there are duplicate timestamp entries. But we also need to consider the possibility of two different ids having the datapoint at the same timestamp. I used the following query, on the google console to get this number. 

SELECT 
  count(id_adv) as total_ids,
  sum(distinct_timestamps) as total_distinct_timestamps,
  sum(collected_timestamps) as total_collected_timestamps,
FROM
  (SELECT
    id_adv,
    count(distinct(timestamp)) as distinct_timestamps,
    count(timestamp) as collected_timestamps
  FROM
    `movilidadcovid.Movilidad.Hermosillo`
  WHERE
    DATE(timestamp) BETWEEN "2020-01-01"
    AND "2020-12-31"
  GROUP BY id_adv);

As shown in the table below, there is a difference of 935988 rows between collected and distinct timestamps. This means that there are these many entries, that are duplicate.

2. ID wise duplicate timestamps

I also queried the number of duplicate entries for each ID. This will allow us to investigate in more detail, if required, to see which individuals have the most duplicate entries. And if the duplicate entries are spread uniformly or present for only a small number of individuals. 

SELECT
    id_adv,
    count(distinct(timestamp)) as distinct_timestamps,
    count(timestamp) as collected_timestamps
  FROM
    `movilidadcovid.Movilidad.Hermosillo`
  WHERE
    DATE(timestamp) BETWEEN "2020-01-01"
    AND "2020-12-31"
  GROUP BY id_adv;

I've stored this data in a CSV locally.
